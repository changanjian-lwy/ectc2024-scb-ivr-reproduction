# A81 - an asynchronous fast path for phase 1's turn-off and turn-on (BOUNDARY)

Track A, `CROSS_PAPER_EXTENSION`. Written before any declared run.

## 1. Question

**Where A80 falls short.** The full Verilog controller meets single-module
criterion 2 except for the dither: 2.3-4.0 A against the 1 A threshold,
while the Python event model gives 0.9-1.2 A. A77/A80 trace most of it to
phase 1's comparator-decided low-side turn-off. The comparator reaches the
clocked logic through the 2-FF synchroniser, so the edge lands on the 4 ns
clock grid (about ±1.3 A of edge current at 0.66 A/ns).

**Question.** If that turn-off, and the predictive high-side turn-on that
follows it, run on an asynchronous path in the mixed-signal front end,
does the dither fall to the Python model's level? The rest of the A80
result must stay as it is.

## 2. Model used, and why

**The physical model** (A79's plant, an identical copy), with the
controller in Verilog. The question concerns the implementation
partition: which edges are clocked and which are asynchronous. Only the
implementation-level description has that distinction.

## 3. Sources (read; not in this repository)

- **Chiang and Chen, IEEE TPEL 2009.** The ZVS controller is built from
  comparators, a sample-and-hold and an RS latch, with no clock. The
  predictive turn-on is generated by that asynchronous chain, with the
  circuit delay compensated.
- **Schaef et al., ISSCC 2019** (P25's reference [22]). The ZCD is an on-
  chip comparator path. Its trip point is digitally trimmed by the clocked
  controller, which only supervises the fast path.
- **TI LMG1210 datasheet.** In PWM mode, the dead time between the two
  outputs comes from a delay (0.8-20 ns, set by a resistor) started by the
  opposite edge inside the driver. That is an asynchronous delay line.

## 4. Design (`rtl/`, a copy of A80's RTL; A80's files unchanged)

**New option `cfg_async`.** It applies to phase 1 in mode P only.

**Clocked logic (Verilog).**
- **Arming.** It raises `arm1` while phase 1 is LOW in mode P, and it no
  longer reacts to the synchronised comparator for that turn-off.
- **Codes it provides:**
  - the comparator trim code (threshold), as before;
  - the delay-line code `dt_pred[0]`.
- **Edge report.** The front end's TDC reports the edge through `a_valid`
  and `a_tlo`: the command-equivalent time of the low-side turn-off, in
  LSB. The logic then:
  - sets `t_lo = a_tlo`, marks the turn-off as current-decided, and pulses
    `lo_pulse`;
  - records the high-side turn-on the delay line makes at
    `t_on = a_tlo + dt_pred`, pulses `on_pulse` (so `t_ref` and the slots
    follow), and enters HIGH;
  - still times the high-side turn-off at `t_on + Ton`.
- **It emits no gate event for these two edges.**
- **The phase-1 restart (400 ns) is kept** on the clocked path. It drops
  `arm1`.

**Front end (behavioural, in the bridge).**
- **Comparator and latch.** An armed comparator plus latch fires at the
  plant step where `i1 <= threshold`. The step resolution is 10 ps.
- **The two edges it makes:**
  - the SL1 turn-off at `t_c + t_async + t_drv`;
  - the SH1 turn-on at `t_c + t_async + dt_pred + t_drv`, through the
    programmable delay line.

  Here `t_c` is the crossing, `t_async` = 1 ns is the comparator and latch
  (`PROJECT_DECISION`; Schaef's comparator is sub-ns), and `t_drv` =
  10 ns.
- **TDC.** It reports `t_c + t_async` quantised to the 125 ps LSB, one
  clock later.
- **Measurements.** The predictive early/late measurement and the
  residual-sign measurement work as before.

**Regression gate.** With `cfg_async` = 0, A81 must reproduce A80 case f2's
sections bit-identically. This is run g0.

## 5. Runs

A80 case f2's setup:
- all-zero start, 30x ramp, load and handover at 88.61 us, 388.61 us;
- 7.5% target (-9.375 A);
- loop ki 0.25 ns/V;
- 250 MHz, 125 ps edges, 10 ns driver.

## 7. Decides / does not decide

Decides:
- whether the clock-quantisation dither of the Verilog controller comes
  from phase 1's comparator-decided edge;
- whether an asynchronous path of the kind in the literature removes it.

Does not decide:
- the latch and delay-line circuits themselves (behavioural here);
- metastability at the boundary where the TDC result enters the clock
  domain (modelled as a clean one-clock handoff);
- the Ton-LSB part of the dither (Roberts' minimum-duty-increment method
  is a separate step).
